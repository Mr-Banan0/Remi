# 固定候选生成过程的 Jev 对照

查询边界快照固定了可见数据库；在线 Planner 仍会生成不同措辞的查询。例如同一问题的 V75、V77 候选池分别为 46、47 条，互相各有 4、5 条独有候选。因此这两次整体 Search 结果适合比较实际运行表现，重排的单项贡献需要更严格的配对实验。

实验命令通过 `--frozen-planner` 读取同一数据库来源的完整 Search 报告，按原顺序重放首次决定和修正决定，并使用该次查询记录的服务时钟。API 请求保持普通 Search schema。此模式属于实验脚本，生产服务继续正常调用 Planner。记录用尽时产生明确的实验错误。

两组均使用相同原始查询、快照、Planner 输出、时钟、检索代码和原文卡片。默认组使用当前原文输入；`--full-rerank-cards` 组将派生摘要和记忆正文同时交给 Jev。两组使用同一提示词和评分协议。结束后检查每题候选文档集合、原始 RRF 分数和服务降级情况，再比较排名。

重放不产生 Planner 模型请求，耗时不能直接当作完整生产 Search 延迟。嵌入和 Jev 继续调用真实供应商；发生降级的配对需要明确标记并重新验证。

两个离线测试验证首次及修正输出顺序、原记录不被修改、缺少输出或用尽时明确失败；快照完整性测试继续验证数据库隔离。

## 首轮配对结果

使用 V74 原始查询快照、V78 记录的 Planner 输出与查询时钟、冻结提交 `d40cea6`。13 个主问题和 3 个生命周期查询的候选文档集合及原始 RRF 分数逐一相等。主问题两组均无降级；生命周期第一题两组保留同一个已记录的 `decision_invalid` 退化，生命周期均为 3/3。

| Jev 输入 | R@10 | MRR@10 | R@100 |
|---|---:|---:|---:|
| 仅原文 | 82.48% | 78.85% | 93.59% |
| 原文与派生摘要 | 85.47% | 79.49% | 93.59% |

两组的主要差异出现在 Q2、Q7、Q8、Q11；正确摘要对某些直接事实和时间细节有帮助。结合独立错误摘要压力测试，当前证据支持“摘要的真实性影响排序”，尚不支持全面去掉摘要能够稳定提高 Golden 成绩。

结果目录为 `.local-data/paired-rerank-source-20261102-r1/` 和 `.local-data/paired-rerank-full-20261102-r1/`。下一项完整试验范围是原文支持度与摘要效用的联合判断：先用独立的正确／错误摘要样本检查，再在固定候选池上验证排名与成本，只有得到稳定收益才采用新的生产协议。

## 原文支持度试验

实验专用 `--grounded-rerank` 同时评估原文贡献、完整卡片贡献，以及原文对派生摘要的支持度。最终分数为 `support * full + (1 - support) * source`。三个判断在同一个 Jev 批请求中提交，GPT 调用数保持不变；Jev 判断数量增加，需要测量真实候选规模下的成本与延迟。生产协议暂时保持现状。

独立错误摘要压力测试 12/12、正确摘要的指代／时间／归属测试 12/12 通过，两组都交换候选顺序。小样本每批三个候选的耗时约 1.4–2.5 秒。三个离线测试通过，覆盖评分混合及既有 Planner 重放契约。结果文件为 `/private/tmp/remi-grounded-summary-stress.json` 和 `/private/tmp/remi-grounded-context.json`。固定候选池试验继续采用与前两组相同的 V74 快照和 V78 Planner 记录；以实际重排收益和成本决定是否进入生产。

首轮混合评分的 16 个查询候选及 RRF 分数与对照完全相同。R@10 为 83.76%，MRR@10 为 73.72%，平均重放耗时 6.83 秒。然而三批分别含 47、46、43 个问题的请求返回 HTTP 400，Q4、Q9、Q13 因此降级；该轮保留为失败运行记录，无法用于证明混合评分优于对照。实验改为按实际判断数量分批，以 24 项作为保守的试验批量，并保持两并发。此批量是实验参数，尚未确认供应商的确切上限。测试覆盖时间判断计数及完整结果回收。全套离线测试在初版实验后为 506 项通过，分批改动的针对性测试为 2 项通过。

分批复测结果保存在 `.local-data/paired-rerank-grounded-20261102-r2/`：全部 16 项候选文档及 RRF 与完整摘要对照相同，主问题无降级、无供应商错误，生命周期 3/3。R@10 86.32%，MRR@10 79.49%，R@100 93.59%；平均重放耗时 7.24 秒、P95 8.98 秒。完整摘要对照为 R@10 85.47%、MRR@10 79.49%、平均 6.33 秒。混合评分仅多命中一项前十证据，MRR 持平而平均耗时增加约 14%，暂时保留为实验方案。当前结果不足以支持生产替换或稳定最优结论。

## 超限原因复核

真实失败请求为 227,660 字节、47 项判断，HTTP 400 的嵌套错误明确为 `max_tokens_exceeded`。40、41 个短问题均成功，证明问题数量本身不足以解释错误。24 项仍仅是历史实验的保守分批设置。生产 V82 在明确的上下文超限或 HTTP 413 后递归拆分请求，完整保留判断项；真实失败负载拆成 23、24 项后均成功，共返回 47/47 个评分。恢复耗时约 5.38 秒，包含最初失败请求；单个问题仍超限时进入既有失败处理。
