# V45：无类型主体连线与关系记忆

日期：2026-10-26。实验 pipeline：`G11-untyped-subject-links-v45`。

## 主体阶段职责

主体模型接收当前原文、同会话最近一条上下文、关键词主体候选和身份依据。它完成四项工作：

1. 找出当前原文中的 individual 与 organization。
2. 对每个主体选择 create、reuse 或 pending。
3. 追加当前原文明确提供的名字、别名以及只适用于一个主体的字面标签或角色。
4. 当当前原文明确关联两个主体时，返回一个无类型端点对及当前来源。

主体 connection 的持久结构只有 `id、owner、endpoint_ids、source_ids`。稳定 ID 由无序端点对生成，多次出现追加来源。主体模型输入省略旧 connection；程序按稳定 ID 完成合并。

主体 prompt 和 Schema 不包含关系类型、方向、状态、时间、Fact、Event 或其他记忆维护规则。设备、地点和项目也不进入主体输出。

## 记忆阶段职责

记忆模型接收已经固定的主体 P 句柄和程序完成召回后的记忆候选：

- 持续关系、隶属状态及其他可持续命题写入 `fact`，选择所有参与主体。
- 关系的开始、变化或结束写入 `event`，保留发生时间、状态和全部参与主体。
- 原文同时明确表达一次变化及变化后的持续状态时，两项内容具有独立长期价值才分别保存。
- 无类型 connection 提供图导航；查询关系含义时读取 Fact／Event 的正文、来源和修订。

## 退出的路径

主体 prompt 中关于愿望、结束状态、引语语义和后续记忆阶段的说明已删除。主体模型不再接收已有 connection。运行模块中用于把旧 relation 卡转成 Fact 的实验适配已移到历史验证脚本，当前 Add 只有一条职责链路。

## 验收

- 主体模型请求中只有身份、别名、描述、引用和无类型端点对规则。
- connection 拒绝任何关系类型、方向、正文、状态和操作字段。
- 同一条关系原文可以同时生成无类型主体边和带双主体的 Fact。
- 关系 Fact 与主体边独立存储、独立校验。
- 已有六个逻辑集合与 schema_version=13 保持，本次修改不创建数据库表。
