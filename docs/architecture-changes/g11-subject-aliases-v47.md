# V47：主体本名与统一别名

日期：2026-10-26。实验 pipeline：`G11-subject-aliases-v47`。

## 主体合同

主体持久结构由三项身份数据组成：稳定 `id`、本名 `name`、有来源的 `aliases`。`aliases` 统一保存原文明确用于指代该主体的名字、昵称、简称、社会身份、角色和物种称呼。每条别名保留来源、原文和观察时间。独立 `references` 保存本轮指代表达，用于支持跨轮身份复用。

`individual` 表示具体的人或动物，`organization` 表示公司、机构或团队。设备、地点和项目保留在事实、偏好、经验与事件内容中。

## 维护流程

主体模型读取当前原文、最近一条上下文、关键词候选及每个候选的身份依据，输出本轮完整主体视图。每个主体选择 `create`、`reuse` 或 `pending`，并只提交当前原文中出现的新增别名。程序校验主体归属、身份依据、别名字面来源和时间可见性，随后生成或复用稳定 ID。

本名与别名共同参与关键词召回。相同社会身份可能命中多个主体，程序完整保留这些候选，由主体模型结合本名、上下文和历史依据判断。主体阶段只维护身份；主体之间的持续联系进入 Fact，联系的开始、变化和结束进入 Event。

## 退出的结构

独立 `descriptions` 字段及其召回、校验、修正和模型输出路径已删除。该字段与别名承担相同的主体定位职责，双轨结构会产生来源校验差异和候选排序分叉。历史实验夹具继续保留旧字段，用于重放旧结果；当前运行合同只接受 `id`、`name` 和 `aliases`。

沿用六个既有逻辑集合，不新增数据库表。生产 API 继续使用 V32，V47 在主体专项和 Golden 验证完成后单独评估推广。
