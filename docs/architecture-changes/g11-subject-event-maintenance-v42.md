# V42：主体优先的事件维护

日期：2026-10-23。pipeline：`G11-subject-event-maintenance-v42`。

## 顺序与职责

1. 保存当前原文与请求检查点。读取同会话最近一条原始消息解释指代。
2. 按名字／别名优先、描述其次召回有限主体候选。主体模型沿用当前 C 引文、B 身份依据、create／reuse／pending 和别名协议。
3. 程序固定本轮身份与 P 句柄。主体联系继续提供导航。
4. 从当前主体关联的历史记忆并集召回；共同参与者和原文词法相关性参与排序。待定同名候选历史明确保留不确定性。完整卡片最多 8 条，召回材料预算 24000 字节。
5. 第二次模型调用读取原文、本轮参与者和历史卡，选择新建、维护已有事件或待定。事实、偏好、经验继续按来源追加。
6. 程序逐条检查来源、引用、目标类型、修改字段、时间表达与参与者，最多共享一次协议修正，保留已经通过校验的条目。
7. 主体、事件修订、图边、检索文档与应用检查点原子提交。事件和主体均检查维护前快照；并发变化时清除过期计划，重试重新召回与计算。

## 事件协议

`operation=create|update|pending`。`target_id` 指向提供的 M 事件；`changed_fields` 支持 content、participants、mode、context、status、planned_at、event_at。

update 保存完整可读内容，并明确列出修改字段。未列出的结构字段保留，参与者替换需要本轮完整身份依据。历史修订和全部来源持续保留。重复的相似活动使用独立事件。每个旧事件每次输出最多一个 update。

`time_expression` 是当前原文中的时间表达，`time_field` 选择计划或实际日期。修订 `time_evidence` 保存字段、表达、来源、原始消息日期、解析值和精度。空锚点的相对时间保持未知；可解析日期替换正文相对日期，同时保留下午等限定词。计划和实际日期分别保存，完成更新保留既有计划日期。

`related_memory_ids` 保存有当前引文支持的事件关联。更新事件时，程序把已有且有来源的导航边投影到新修订。缺少当前来源、错误目标或待定参与者无法覆盖已存事件。

## 保留与替换

保留主体语义、名字／别名／描述、C／B 引用、最近一条上下文、来源保存、六个集合、Search、检索文档及请求恢复机制。

替换实验 Add 的共用提前记忆召回与同名顺序切换；当前引擎统一主体优先。删除旧 `subject_memory.py`、`subject_memory_review.py` 及其专属分支测试。通用句柄渲染与旧提取协议测试继续在 `subject_extraction.py` 中维护；当前供应商只调用新事件协议。

生产服务 V32 继续使用原入口，推广需独立语义验收。共享 Revision 增加可选时间证据字段，历史数据默认空数组，既有读取方可以继续加载旧修订。新增表数量为 0。

## 验收边界

离线验证检查生命周期、来源／用户范围、主体并集、待定保存、旧版本、图边、精度、修正保护、并发与断点恢复。真实 GPT 小样本固定输入、记录输出与检查点，并分开保留首轮、规则澄清后的回归和新增场景。测试数据与评分规则只存在于测试／验证脚本，运行时无数据集人物或答案规则。

真实模型结果记录于 `docs/subject-v42-results.md`。Golden 和生产推广使用独立验收结果。


## 历史补录与并发一致性补充

事件更新使用消息时间下的可见修订作为基底，追加修订后由 observed_at 决定当前视图。较新版本和其参与者保持原样。程序分别保存用于模型判断的历史 revision_id，以及召回时完整记录的指纹；写入前和事务内对完整记录检查并发变化。本轮参与者校验针对实际追加的修订。

协议修正保留先前通过的条目及其目标，冲突的新条目进入待定。错误字段的原始类型和值可以进入修正反馈，合法 ID 才转换为模型句柄。两次正常调用和共享一次修正预算保持一致。V42 检查点标识保留，以支持现有待处理请求续跑。
