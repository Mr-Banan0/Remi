# Jev 连接故障恢复

基于 Remi 0.2.19 的工作区改动。范围为 Search 的 Jev 传输恢复和诊断。

## 执行规则

- 正常执行保持每批 8 条、最多 2 个并发工作线程，每批最多 2 次请求。
- 可重试的传输错误和 HTTP 408/429/5xx，首次失败后等待随机 0.5～1 秒。剩余预算须覆盖等待和至少 0.25 秒的请求机会。
- 同一次 rank 调用中的批次共享连接健康状态。ConnectError、ConnectTimeout、ProxyError 连续累计到 3 次时打开停止信号。
- 收到 HTTP 响应会清零连续连接失败计数。停止信号打开后在本轮保持生效。
- 停止信号唤醒等待中的重试，并跳过后续批次。已在途的请求完成后仍可贡献分数。
- 下一次 rank 调用创建独立健康状态，可以重新尝试连接。
- HTTP 服务错误保留每批两次的调用预算；连接停止计数专用于建立连接失败。

旧的固定 50 毫秒重试等待由上述退避规则替代。来源内容、排序问题、评分解析和上下文超限拆批保持原有规则。

## 诊断

实际请求使用 `kind=rerank`，记录状态、耗时、尝试次数、失败阶段、异常类型链、系统 errno、连续连接失败数、停止状态和重试等待。

跳过的批次使用 `kind=rerank_skipped`，记录跳过原因和问题数量，区分物理调用与本地停止。异常消息、认证头和请求正文均不进入新增日志。底层 HTTPX trace 提供的阶段用于区分 TCP、TLS、代理隧道等失败位置；缺失阶段时保留类型链，进一步定位仍依赖实际故障证据。

## 验证边界

离线 MockTransport 测试覆盖健康双并发、孤立失败恢复、持续故障停止、下次调用恢复、已得分保留、预算不足、HTTP 服务错误和日志脱敏。既有上下文拆批、时间评分和来源证据测试一起回归。

本轮验收以离线测试为准；在线 Golden 和真实网络故障复现未执行。阈值 3 是限制故障放大的工程初值，不代表已测定供应商最佳参数。
