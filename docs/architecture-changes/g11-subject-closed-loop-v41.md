# V41 主体闭环：证据、名字与记忆参与者

## 目标与范围

本轮稳定主体优先链路的四个连续环节：确认当前身份、保存当前名字、下轮关键词召回、把记忆连接到实际参与者。统一主体与无向导航联系、事实／偏好／经验／事件四类记忆、共用召回以及检索排序沿用当前设计。

实验 pipeline 为 `G11-subject-closed-loop-v41`。当前同一名称／别名命中至少两个不同ID时仍执行记忆优先；其余执行主体优先。名称命中数选择执行顺序，模型结合当前原文与候选证据判断同一身份、新身份或待定。生产入口保持 V32，推广条件为实验语义验收通过及服务入口、检查点切换完成。

## 主体阶段的输入与输出

输入包括完整当前原文、两条解释上下文、关键词主体候选及其有来源的身份依据。程序为当前原文生成稳定片段 C1、C2 等，保留来源、原文起止位置和准确文字；B编号继续标记候选主体拥有的历史身份依据。

模型返回 `subjects` 和 `connections`。主体具有本轮整数ref、create／reuse／pending、目标ID、显示名、类型、字面名字列表、描述和 `reference={evidence_id,basis_id}`。每个当前主体选择C证据；reuse选择属于目标ID的B依据，create／pending的basis_id为null。程序从C复制原文，校验来源所有权、可见时间和B归属，编译内部来源引用。

别名由模型显式归属到主体；程序核对字面来源、去重并追加。当前使用的短名、昵称也进入该列表。指代的来源证据独立保存，供未来身份依据使用。显示名、可搜索名字、指代证据分别承担呈现、检索和身份解释职责。合法证据片段证明引用来源，人物归属继续由语义验收判断。

## 主体到记忆的交接

程序从具有合法当前C引用的主体建立本轮参与者视图，包含已确认身份与真正的待定指代。缺少合法当前引用的行留在审计中。内部ref生成稳定 `P{ref}` handle，记忆模型只看到当前P编号、名字、状态和当前证据。

历史人物用独立文字标签解释历史记忆；已确认同一ID时，程序展示其与当前P的对应。存储ID与内部整数ref保存在程序映射中。模型的四类记忆输出 `participant_handles`，程序检查合法范围、重复引用及来源后，恢复内部ref并编译写入计划。合法handle与实际人物语义分别评价。

## 错误反馈、保存与调用预算

具体的协议错误包含字段路径、错误代码、返回值和允许范围。原始模型输出与校验问题一起保存，并进入同一参与者词汇下的修正请求。正常每单元两次模型调用，两阶段共享最多一次协议修正；供应商网络重试独立统计。

复用原文、记忆修订、图边、索引与请求检查点的原子保存。现有六个逻辑集合用于本轮MemoryStore实验；新增物理表数为0。旧实验在各自冻结runtime中复现，当前实验退出自由抄写mention与记忆阶段的双参与者编号协议。

## 验收

先运行离线协议、来源可见性、检查点和完整回归测试，再使用独立中英文跨轮场景重复三轮。分别评价主体覆盖、当前范围、ID选择、别名保存、下一轮名称召回、逐条记忆参与者、程序协议与调用预算。关键语义场景三轮通过后冻结代码并运行同一输入的GPT Golden；结果与版本、配置、实际请求响应绑定保存。
