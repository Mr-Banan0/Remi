# G10 简化范围与验收门槛

G08 的 Golden R@10 为 76.07%，G09 为 73.08%；两者完整命中均为 9/13，G09 主集逻辑 Add 从 62.14 秒增至 95.22 秒。G09 的完整结构校验通过后仍出现语义误操作。当前目标是降低一次维护的语义负担，让程序约束能够保护相邻记录。

| 范围 | G10 做法 | 原因 |
| --- | --- | --- |
| 保留 | 两阶段 GPT、统一主体、独立 relation/event、原文、稳定 ID、修订、混合检索、Search/Jev、事务／恢复、六表 | 已有基础能力继续参与闭环 |
| 修改 | 程序按精确名称对齐主体，候选只提内容、名称和来源 | 将确定性字段处理交给程序 |
| 修改 | 每项 create／keep／patch_event／pending，一次共享局部修正 | 明确各项结果并保留有效兄弟项 |
| 收窄 | 关系／状态新增与保持；已确认计划事件改期／完成／取消 | 保留高价值且可限制字段范围的维护闭环 |
| 退出生产合同 | 五类关系生成、主客体／角色／属性字典、关系结束撤回、主体生命周期、跨记忆语义联系 | 这些职责尚缺独立稳定的语义验收；原文继续保存细节 |
| 图投影 | mentions、supported_by、revises | 主体导航、来源追溯、事件修订各有明确作用 |

静态严格 Schema 大小：ProposalDraft 1164 字节，MaintenanceDraft 2940 字节。G09 分别约 5.5 KB、16.2 KB。候选 ID 由程序按窗口内位置分配；每次调用的可选来源、候选与历史目标由当前输入确定，模型生成最大输出预算为 6000 tokens。Schema 变小只表明协议负担减少，实际质量与延迟以真实调用为准。

独立验收先覆盖：新计划＋独立状态 → 改期 → 完成／取消 → 新发生获得新 ID → 指代不明进入待定。核对数据库实际字段、旧关系不变、证据累积、主体连接和修订；原文可检索单独验收。

验收器使用四个领域、两种措辞共八个合成对话，各六次 Add，最终复验增加原文 Search 冒烟检查。期望字段不传给生产链路。首次开发预检和后续冻结版验收分开记录；所有失败原样保留。任一关键维护断言失败时，Golden 保持未运行状态。

模型训练、Golden 定向提示、特定人名／答案词匹配、场景规则分支、数据集字段映射和题目缓存均在本次范围之外。词法边界、日期等价、来源隔离和更新权限以通用合同及独立测试验证。
