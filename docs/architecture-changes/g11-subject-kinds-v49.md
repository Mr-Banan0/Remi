# V49：主体名字与三类主体

日期：2026-10-26。实验 pipeline：`G11-subject-kinds-v49`。

## 主体契约

主体只保存稳定身份信息：

| 字段 | 含义 |
| --- | --- |
| `id` | 程序生成的稳定主体 ID |
| `name` | 第一次确认的名字；尚未出现名字时为 `null` |
| `aliases` | 后续确认属于同一主体的其他名字、昵称、简称或组织改名 |
| `kind` | `person`、`animal`、`organization` 三选一 |
| `references` | 当前指代及历史身份判断所依据的原文 |

`person` 表示具体的人，`animal` 表示具体动物，`organization` 表示公司、团队和机构。狗、猫、宠物等具体动物类别属于事实记忆；职业、社会身份、亲属关系和主体之间的联系同样由事实或事件记忆维护。

## 写入职责

主体模型读取当前原文、最近一条上下文、名称／别名关键词候选及其身份依据，只返回本轮出现的主体。搜索候选表示可能身份，辅助上下文用于解析当前原文中的指代。模型决定 `create`、`reuse` 或 `pending`，并提供名字、类型、当前指代证据和本轮新增别名。程序验证名字与别名都来自当前原文，复用保持已有 `name` 和 `kind`，随后生成稳定参与者句柄供记忆阶段使用。

同一当前名字或别名命中多个同类型 ID 时，reuse 需要唯一身份依据；缺少区分证据时选择 pending。create 与已召回别名重合，或在新增别名时与已有本名重合，会进入一次共享修正。修正轮选择 reuse、pending，或再次 create 来确认原文明示的新主体。唯一名字命中的 reuse 由程序补全对应身份 basis，模型继续负责身份语义判断。

记忆模型负责事实、偏好、经验和事件。具体动物类别随原文写入这些记忆，并连接到已经固定的动物主体。持续关系写入事实；关系的开始、变化和结束写入事件。

## 召回边界

主体召回只使用 `name` 和 `aliases`。`kind` 用于候选之间的身份判断，不作为关键词召回词。具体动物类别不会把所有同类动物同时召回。主体固定后，记忆召回按本轮主体范围筛选；置信度不足时，程序补入无主体记忆并统一排序。

V49 删除 V48 的 `species` 字段及其召回分支，因为具体动物类别已经属于事实记忆，继续在主体卡保存会产生两份状态和类别词误召回。沿用 sources、memories、objects、edges、requests、search_documents 六个既有逻辑集合，新增数据库表数量为 0。
