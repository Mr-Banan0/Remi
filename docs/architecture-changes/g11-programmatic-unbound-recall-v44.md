# V44：程序化无主体补搜

日期：2026-10-26。实验 pipeline：`G11-programmatic-unbound-recall-v44`。

## 目标与边界

主体阶段固定本轮主体 scope。初始记忆池只包含与已确认主体相交的记忆；一条记忆同时包含当前主体与其他主体时可以进入。只绑定其他主体的记忆保持在本轮 Add scope 外。待定主体不打开任何旧主体的记忆范围。

无主体记忆承担缺失主体标注的历史候选。程序仅在主体范围内的召回置信度不足时补入无主体记忆，并对两组候选使用同一次 BM25 评分统一排序。最终最多提供 6 张完整记忆卡，继续使用 24000 字节输入预算。

## 置信度

程序在“主体记忆 + 无主体记忆”的允许集合上计算 BM25。主体召回置信度定义为：

`最高主体记忆分数 / 最高允许记忆分数`

主体池为空、最高主体分数为 0，或置信度低于 `0.80` 时触发无主体补搜。比较使用同一候选集合和同一评分器，避免跨集合直接比较原始 BM25 分数。阈值、两项最高分、触发结果和补入的无主体记忆 ID 都写入 trace，后续用 Golden 召回证据校准阈值。

## 模型协议

记忆模型接收程序准备好的最终候选，一次完成 create／update／keep／pending 判断。`recall_query` 字段和第二次记忆决策调用退出。主体模型一次、记忆模型一次构成正常路径；协议修正按需增加一次调用。

## 保持项

- 当前原文和同会话最近一条上下文共同形成召回查询。
- 原始来源、修订快照、并发检查和 24000 字节打包继续使用现有实现。
- sources、memories、objects、edges、requests、search_documents 六个逻辑集合保持。
- Search 的主体导航和事件 related 两跳遍历保持。

## 验收

- 已确认主体的相关记忆可以进入候选。
- 低置信度时，相关无主体记忆可以进入统一排名。
- 只属于其他主体的记忆在初始与补搜阶段都无法进入候选。
- 待定主体不会借名称候选打开旧主体记忆。
- 每个文本单元只执行一次记忆模型决策；请求重放复用检查点。
- 本次修改不创建数据库表。
