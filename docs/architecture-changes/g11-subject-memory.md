# G11 主体与记忆职责拆分（V18 历史）

当前生产合同见 [V19 候选增量维护](g11-subject-delta.md)。以下保存 V18 的设计与实验口径。

本轮沿用统一主体、来源别名、原文联系、独立事件和六表存储，收敛到三个模型阶段。程序在阶段边界固定身份，维护其他记忆时只使用通过校验的主体。

| 部分 | 处理 |
| --- | --- |
| 保留 | 完整原文、六表、用户隔离、消息时钟、稳定 ID、追加修订、同用户串行、幂等、事务与阶段检查点 |
| 修改 | 身份候选召回 → 独立身份维护 → 程序校验 → 按确认身份召回记忆 → 独立记忆维护 |
| 新增 | 第二阶段补提原文主体；按操作分开的身份输出合同；身份／联系矛盾校验；固定主体视图；分阶段检查点 |
| 退出 | 逐对身份布尔判定合同；全局 user_referenced 开关；身份与记忆混合输出；不同身份自动派生联系 |
| 调用 | 普通单元三次 GPT，空阶段按需跳过，共享一次输出修正；连接重试和并发重算单独统计 |
| 边界 | 新别名有来源；现有全库主体合并、历史重绑、撤销与 BFS 保持为独立设计范围 |

## 输入与输出

| 步骤 | 输入 | 输出 | 程序检查 |
| --- | --- | --- | --- |
| 保存来源 | API 用户、请求、消息、时间 | Source、请求指纹、单元 | 用户范围、幂等与时间 |
| GPT 提候选 | 当前原文、解释上下文 | 称呼、身份线索、联系提示、其他独立命题 | 提供过的 Source、字面摘录、候选上限 |
| 身份召回 | 称呼、同用户可见名称和别名 | 候选旧 ID 与来源、临时 refs | 所有权、知识时间和候选预算 |
| GPT 维护主体 | 原文、refs、身份候选 | 每 ref 的身份处置、别名、补提主体、显式联系 | 原文名称、来源、复用权限、无环引用、联系端点 |
| 固定身份 | 已校验身份计划 | ref→ID、主体与联系计划、待定、期望快照 | 独立有效项固定；矛盾项共享一次修正 |
| 记忆召回 | 确认主体 ID、候选内容 | 关联历史与少量全局补充 | 可见时间、最多八卡、上下文预算 |
| GPT 维护记忆 | 原文、固定身份、候选、旧卡 | create／keep／patch_event／pending | 主体只读、目标来自召回、局部事件字段和日期 |
| 提交 | 主体、联系、记忆计划、原文与快照 | 记忆、修订、边、索引、检查点 | 来源、所有权、端点、版本、原子性 |

身份合同按操作定义字段：new／user／pending／unsupported 使用公共来源字段；reuse 额外选择 existing_id；same_as 额外选择 same_as_ref。程序创建新 ID，并要求每个候选称呼都有处置。新增称呼必须落在原文中。名称和描述词作为可搜索入口，同名命中保持候选性质。

每条联系由身份阶段明确输出两个不同主体和原文。程序将有效联系保存为独立 relation 卡及 related 边。别名合一与主体区别各自维护身份；联系必须另有明确计划。其他 relation／state 和 event 使用独立记忆阶段，事件补丁仅作用于明确陈述的计划事件，保留其他字段与既有来源。

三个阶段共享一次输出修正。已通过的主体与记忆候选在修正中保持固定；修正后仍有缺口的项保留待定和原因，原文持续入索引。请求断点分别保存提取、主体计划和记忆计划；索引失败重试复用这些结果。并发修改旧主体或记忆时重新召回。

完整流程、限制与当前验证结果分别见 [当前架构](../current-architecture.md) 和 [验证记录](../subject-memory-validation.md)。本轮沿用 schema_version=12，阶段版本更新为 G11-three-stage-v18。改动保持未提交。
