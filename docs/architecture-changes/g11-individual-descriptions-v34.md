# V34 主体验证：个体、组织与有来源的描述

范围：当前主体实验使用 individual（具体人或动物）与 organization（组织／团队）；aliases 保存名字、昵称与简称；descriptions 保存原文中的短描述及来源。每次主体模型输出 create／reuse／pending、名字增量、描述增量及无向主体连接。程序生成稳定 ID，复制原文与观察时间，并分别审计身份、别名和描述。描述按来源追加保留，角色变化沿用身份；当前状态由完整原文和后续四类记忆判断。

实现：experiments/subject_identity.py 为实验提供单一的个体身份模型、来源校验与物化路径；experiments/subject_connections.py 采用新合同和文本输入。描述与名字共同召回候选，存在多个匹配时全部保留供身份判断。实验的共享候选池使用名称／描述和一层有来源连接，验证描述可被后续轮次检索；生产 Add 的混合召回、持久化、四类记忆及事务继续使用 V32。

退出：当前实验的 person／animal 类型、将物种与角色混入别名的示例，以及实验中依赖生产 person 校验的路径。原因是新的主体合同统一为个体并单独保存描述。V33 结果通过冻结代码和前置 commit 保留；旧格式评测输入仅在验证脚本的 fixture 适配器中转换，运行时身份决策遵循新合同。

保留：12 组独立英文示例的原文、create／reuse／pending、稳定 user 身份、按 source_id 引证、无向连接合并、来源追加和至多一次协议修正。示例中的 cat／dog 从别名迁到描述。核心决策提示使用通用身份与证据规则；评测名字、分数及期望答案留在验证侧。

调用与验收：每轮正常一次主体模型调用，原 28＋10 组直接样本使用相同原文和主体候选；4 组原连续维护和4组新描述跨轮案例。离线 363 passed。首轮发现来源编号协议缺口并保留诊断结果；程序修复后重新冻结，全套真实运行，结果与失败原文完整保存。评分同时报告原身份／可检索标签覆盖和新字段分离；V33 输出仅在评测侧投影字段后采用同一规则比较。纯身份对齐与描述完整性分别报告，歧义关系的待定要求计入身份安全检查。

数据范围：主体真实验证使用 MemoryStore，物理数据库和新增表均为 0；离线 SQLite 回归沿用获准的既有六表。Golden 属于独立整体验证，本轮仅运行主体测试。

最终结果：28组18/28，扩展10组6/10，原跨轮3/4，新描述跨轮1/4。来源编号修复与完整边界见 [V34结果](../subject-v34-results.md)。
