# V37：关键词主体召回与两条对话上下文

日期：2026-10-23。实验 pipeline：`G11-keyword-subject-recall-v37`。生产 HTTP 默认仍使用 V32，现有服务调用方继续使用该入口；本轮更改和验收作用于完整实验 Add/Search。

## 当前链路

1. 程序取当前用户原文和最近两条先前消息，按对话顺序排列；每条先前消息沿用 4,000 字节显示上限。
2. 在当前用户、当前时间可见的主体全量名字、别名和描述上做词法匹配。名称与别名等权；优先级依次为当前名称／别名、上下文名称／别名、当前描述、上下文描述。同档以命中词组长度排序，同分以稳定 ID 确定顺序。匹配沿用 NFKC、大小写／空格规范化及拉丁名称词边界。
3. 选中已有 canonical user，加最多五个其他主体。按身份 ID 保留候选，同名身份保持分开；超过数量上限时，输入明确提示候选列表为部分列表，trace 记录被数量限制排除的 ID。
4. 将候选身份卡按归一化名称去重，优先展示命中的名字和描述；每卡最多八个名字证据及三个描述。每个主体提供最多两项互补身份依据，优先各一项名字与描述；canonical user 另有 API 用户依据。所有存储名字仍参与匹配。
5. 为历史身份依据展示准确原文片段，每个片段通常最多 800 字节，完整依据短语获得足够空间。完整主体、别名、描述与原文保留在存储中，程序从完整记录验证并追加有效增量。长消息的上下文截断与身份原文取证分别处理，候选依据可以来自消息显示范围之外的完整已存原文。
6. 在同一快照中保留四类记忆的原文／上下文混合检索和一层关联历史通道，最多装入八条历史记忆。先固定主体候选，再按预算装入完整记忆卡及来源；超出预算的卡跳过，后面的较小卡继续尝试。
7. 主体模型接收当前原文、两条先前消息、精简身份卡、身份依据及候选之间的已有导航联系。程序用同一投影限定引用来源。模型输出继续采用 subjects／connections；复用、新建与待定由模型依据原文判断。
8. 主体校验完成后，四类记忆模型读取同一快照保留的历史和已固定主体视图。程序校验、按来源追加记忆并原子提交。

关键词命中产生身份候选。当前原文中的“另一位”、角色差异等继续由模型判断；信息不足时保留待定。通用运行时代码读取 API 原文与用户记录，评测人名、期望值与旧错误留在离线分析脚本中。

## 修改边界

| 部分 | V37 处理 |
| --- | --- |
| 主体选择 | 名称／别名优先于描述；已有 user 加最多五个其他主体 |
| 主体输入 | 最近两条先前消息、精简身份卡与身份依据 |
| 共用召回 | 主体先固定，四类记忆随后填充；主体专项与完整实验共用候选构造器 |
| 历史参与者与一跳邻居 | 参与记忆检索，候选主体由关键词相关性决定 |
| 预算 | 24,000 字节保守计算已渲染身份材料与序列化完整历史卡；当前原文、两条消息正文与固定提示独立计量 |
| 预算处理 | 优先精简可选名字／描述展示，再跳过过大的历史卡；选中主体 ID 保持固定 |
| 主体引用协议 | 当前 mention、历史 B 依据、来源／归属／时间校验保留 |
| 受保护的一次修正 | V36 的结构化错误、前次输出、有效部分保护及未确认提议撤回保留 |
| 调用预算 | 每单元正常一次主体模型、一次四类记忆模型，共享最多一次协议修正 |
| Search | 原文／图／时间和重排流程保留；查询主体词法匹配沿用该排序，搜索种子数量上限保留 24 |
| 生产入口与数据 | 生产 src 保持 V32；旧实验继续使用冻结代码和快照 |

旧的“先保护历史参与主体、再从尾部删除可选主体”组包逻辑已退出：当前设计先保证关键词身份候选的可见性，再分配记忆上下文预算。主体专项的独立一跳主体扩展也由共同候选构造器替代，避免专项与完整实验采用不同选择规则。

两条上下文适合处理近邻指代；更早的身份信息通过有来源的身份卡提供。数量限制与描述的词法匹配仍可能遗漏主体，完整语义效果由真实模型和后续完整实验分别验收。

全套离线 427 passed、0 skipped，新增 20 项关键词／证据／上下文／共用快照回归。旧 Golden 的 318 条原文仅进行离线候选重放，模型调用为 0。结果与边界见 [V37 验证报告](../subject-v37-keyword-results.md)。
