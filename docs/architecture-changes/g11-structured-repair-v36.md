# V36：可定位的主体校验与一次修正

日期：2026-10-22。当前完整实验 pipeline 为 `G11-structured-repair-v36`；生产服务入口维持 V32。用户授权完善主体校验信息，使模型能根据具体失败调整，并保护已经通过的主体、别名和连接。

## 调整原因

V35 的修正调用把错误简化为代码字符串。主体 ref、字段路径和上一次模型输出没有进入修正请求；同一主体遇到第一个失败即退出检查。Rhea／Ray 的真实 trace 中，模型修正后仍引用历史来源，还重排了 ref、漏掉 Momo 别名与拥有联系。

V36 使用单一的结构化校验结果，原来的首错分支已经退出。修正输入包含原始任务、上一轮 assistant JSON 响应，以及程序生成的英文反馈。输出继续使用同一 `subjects`／`connections` 合同。

## 输入与输出

| 步骤 | 输入 | 输出 |
| --- | --- | --- |
| 首次主体调用 | 当前原文、必要前文、共用候选、身份依据 | 主体操作、名字／描述增量和无向联系 |
| 程序校验 | 模型原始结果、同一来源视图 | 定位到主体 ref 和字段的 issues；已通过的身份、有效增量与连接 |
| 构造修正请求 | 原始任务、上次完整输出、issues、已通过部分 | 保持统一 S／E／B 编号的修正对话 |
| 一次修正调用 | 上述对话 | 同一完整输出合同；依据证据修正失败字段和依赖连接 |
| 保护与复验 | 初次通过部分、修正原始输出 | 恢复被漏掉或改写的已通过内容，统一复验有效结果，分别记录剩余错误和保护动作 |
| 后续写入 | 固定主体视图 | 四类记忆提取、程序编译、向量与原子提交继续使用既有流程 |

每条 issue 包含 scope、path、code、message、ref、actual、expected、source_ids。校验器根据实际约束生成具体信息；模型看到主体编号、字段路径、返回值、要求及相关原文编号。来源 ID 和主体 ID 与原任务及响应使用同一命名空间。

结构校验通过后，程序收集可独立判断的来源、当前提及、证据及身份依据错误。例如来源引用了历史 S2，同时 mention 使用当前 S1 中不存在的 Rhea，两项一起反馈。依赖条件缺失时，该项保持可解释的校验失败。

来源归属和时间可见性继续由程序验证。别名及描述错误独立于已确认身份，并进入同一次修正反馈。程序验证字段与证据一致性；语义上是否同一身份继续由模型结合上下文判断。

## 已通过部分的保护

1. 初次完整通过的主体行按原 ref 保留，包括已有名字、描述和来源。修正响应漏掉、改写或重排时，程序恢复该行并记录保护动作。
2. 身份通过而增量部分失败时，身份字段保持稳定；有效别名和描述保留，失败字段可以补正。
3. 已通过结构与来源检查的连接保留；端点因普通引用错误待定时，连接随修正后的身份重新校验。
4. 重复 ref 或同一旧 ID 占用多个 ref 属于结构性错误，允许合并或重新分配相关 ref，并重新检查依赖连接。其他 ref 的已通过部分继续保留。
5. 完整修正响应可以撤回未确认且当前原文不支持的主体提议，并清理依赖它的待定连接。已通过身份的行及有效增量继续保留；异常修正响应保留原有失败状态。来自异常容器或重复 ref 的结构修复可以补齐必要的 ref。

模型原始修正结果、程序合并后的有效结果和保护动作分别保存。模型自行修正率与程序保护后的通过率分别统计。保留已通过程序检查的内容，可以维持结构与来源约束；该机制的语义准确性仍由专项场景验收。

## 修改范围

| 部分 | 当前处理 |
| --- | --- |
| 主体校验 | `subject_identity.py` 收集相关字段问题后决定身份能否物化；有效名字／描述独立追加 |
| 联系与响应校验 | `subject_connections.py` 对响应容器、连接端点和来源逐字段定位，生成统一 issues |
| 英文反馈 | `subject_validation.py` 生成标准问题并渲染说明；上一轮输出以 assistant 消息提供 |
| 保护合并 | `subject_repair.py` 构造固定区，保留通过部分，并复验依赖关系 |
| 完整实验 Add | 保存初次输出与修正请求检查点；修正请求失败后复用初次结果和相同修正输入 |
| 专项脚本 | 与完整实验使用同一修正构造和保护函数；记录初次错误、最终错误和实际有效输出 |
| 旧诊断字段 | subject_errors 等保留为 issues 的投影，供现有报告和审阅脚本使用；业务校验只有一条实现 |
| 保持 | 主体范围、引用合同、few-shot、召回选择、日期规则、四类记忆、Search 与生产入口 |
| 调用预算 | 每单元正常两次 Add 模型调用；主体与记忆阶段共享至多一次协议修正，网络重试单列 |

候选预算裁剪保持本轮原状。修正输入采用当前已提供的候选与证据，候选覆盖问题单独归属于共用召回。
