# V48：主体名字与动物物种

日期：2026-10-26。实验 pipeline：`G11-subject-names-v48`。

## 主体合同

主体类型为 `person`、`animal` 和 `organization`。每个主体保存以下身份字段：

| 字段 | 含义 | 更新规则 |
| --- | --- | --- |
| `id` | 稳定主体标识 | 程序创建并在后续复用 |
| `name` | 首次确认的真实名字 | 未命名主体为 `null`；首次出现真实名字时写入，之后保持稳定 |
| `aliases` | 同一主体后来出现的其他名字 | 只追加原文明确给出的名字、昵称或简称，并保留来源 |
| `kind` | `person`／`animal`／`organization` | 创建时确定，复用时保持一致 |
| `species` | 动物物种 | 仅 `animal` 使用；从原文字面写入并保持一致 |
| `references` | 当前或历史指代依据 | 程序复制原文片段，用于支持后续身份复用 |

职业、社会身份、属性和主体间联系进入普通记忆。持续状态写入 Fact；开始、变化和结束写入 Event。设备、地点和项目继续保留在四类记忆正文中。

## 维护与召回

程序先用本名和别名进行关键词召回，动物物种作为较低优先级线索。候选卡提供本名、别名、物种及最多两项身份依据。本名依据直接使用简短名字并连接完整原始来源；长原文在模型输入中显示有界节选，存储保留完整原文。

主体模型读取当前原文、最近一条上下文和候选卡，输出 `create`、`reuse` 或 `pending`。程序验证当前原文片段、历史依据归属、本名稳定性、别名来源、类型和物种。匿名主体获得第一个名字后，程序把该名字写入 `name`；后续其他名字进入 `aliases`。

记忆模型接收固定主体视图，维护 Fact、Preference、Experience 和 Event。主体名字维护与记忆内容维护保持两个独立职责，正常 Add 继续使用两次模型调用并共享一次协议修正预算。

## 结构收敛

V48 使用单一主体路径。V47 中作为 aliases 保存的职业、社会身份、角色和物种称呼迁移到对应职责：职业与角色进入记忆，物种进入 `species`。本名只保存在 `name`；一个别名按标准化名字只保存一次。独立 `descriptions` 与主体联系输出继续保持退出状态。

沿用 sources、memories、objects、edges、requests、search_documents 六个既有逻辑集合，数据库新增表数量为 0。生产 API 继续使用 V32，V48 在真实模型语义门槛通过后再评估推广。
