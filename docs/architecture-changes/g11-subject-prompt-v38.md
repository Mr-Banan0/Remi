## 当前链路与目标

当前链路：共用关键词召回及两条上下文 → 主体与联系维护 → 程序校验并固定 ref → 四类记忆提取 → 程序校验和保存。

目标链路沿用上述顺序，主体模型按明确的身份覆盖、身份选择、增量与证据规则完成一次维护。

## 范围与局部变更

- 保持：主体 individual／organization、统一 subjects／connections 合同、现有记录和校验、六个逻辑集合、共享召回及记忆提取逻辑。
- 修改：实验主体提示词、独立示例、主体文本渲染及字段说明；引用字段的来源范围与既有校验对齐。
- 新增：提示词修订的阶段记录、语义示例和传输合同检查、固定输入的真实主体回归结果。
- 退出：普通调用中的修正规则、示例之间隐含连续状态、主体渲染依赖通用文本生成后再做字符串替换的拼装方式。修正调用显式附加相应规则，主体材料直接分区生成。
- 调用预算：正常每单元一次主体维护、一次记忆提取，两个阶段共享最多一次协议修正。测试使用 MemoryStore。

## 顺序与完成标准

1. 规则层级：分区展示；核对原规则逐字保留。
2. 判断顺序：明确识别、分组、身份决策、增量、联系和终检的次序。
3. 输出职责：subjects 覆盖本轮所需身份；aliases／descriptions 表达增量。
4. 身份决策：明确 create／reuse／pending 的条件及证据优先级。
5. 引用要求：当前提及、当前来源与历史 B 依据各有范围；Schema 与既有校验对齐。
6. 描述归属：描述主体身份和区分特征，逐字内容与实际归属分别核对。
7. 联系边界：根据明确联系或共同参与事件提出无向边。
8. 修正阶段：正常规则与按需修正规则分别提供，沿用单条维护路径。
9. 示例独立性：标明示例边界和局部 ID 范围。
10. 示例覆盖：覆盖主体维护的独立判断边界，按真实合同解码和物化。
11. 增量语义：新增名字／描述与已有身份复用保持一致，程序保留已有材料。
12. 动态材料：身份卡聚合候选与依据，按来源 ID 提供原文，省略空框架。

验证：先运行合同及引用检查，再运行完整离线测试，最后用固定独立主体集进行同模型对照。分别统计身份、描述、联系、协议错误、修正和耗时；Golden 保留为后续单独授权的实验。
