# V52：候选级记忆身份门

日期：2026-10-26。实验 pipeline：`G11-memory-identity-gate-v52`。

V52 保留 V51 的三阶段模型调用：主体维护、候选记忆提取、记忆维护。维护模型继续只返回 `ref`、`operation`、`target_id`、`content`、`pending_reason` 五个字段。

V51 Golden 证明 update 修订已经打通，同时暴露出记忆身份过宽：同主体、同类型的独立经历被连续写进一张卡，最长卡达到 17 个 revision。大卡携带多个无关主题和来源，继续吸引后续候选，并占用 Search 候选预算。

V52 在候选与维护之间加入程序化身份门：

- 程序从候选正文与旧记忆正文提取具体主题词，排除参与者名字、日期、状态词和叙事连接词。
- 每个候选最多获得三个具备主题连续性的同类旧记忆。
- update 的 `target_id` 必须属于该候选的 eligible targets；越界选择进入现有一次修正流程。
- 已完成或取消事件保持终态。终态事件回到 planned／desired 会被拒绝。
- 已完成事件的新实际日期代表独立 occurrence，生成新事件。

身份门只缩小模型可选范围，主体 scope、类型、参与者、状态、时间和证据仍由既有阶段确定。模型调用数保持三次，存储继续使用既有六个逻辑集合。

离线 599 项通过，真实事件专项 3/3 通过。完整 Golden 中，记忆从 V51 的 97 条增至 206 条，update 从 113 次降至 61 次，最长 revision 链从 17 降至 9；pending 从 72 降至 32，validation_failed 从 34 降至 19。主集仍有少量长链，身份门后续可改为比较首个 revision 的身份锚点，进一步抑制内容累积后的吸附。

V52 Search R@10 为 61.54%，低于 V51 的 69.23%。独立卡恢复了电影夜证据，但同日相邻事件、设备故障与替代设备、健康限制与恢复过程缺少跨卡桥接。后续检索方案应在保持身份门的基础上，从命中的记忆按会话邻接、共享事件和有边际收益的图扩展补充证据。
