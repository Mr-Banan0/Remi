# V40：按名称命中 ID 数量决定维护顺序

## 目标与边界

本轮在完整实验 `G11-name-collision-routing-v40` 实现确定性路由。对当前原文中每一个命中的已有名字／别名，统计所属主体的不同 ID；同一称呼命中至少两个 ID 时先处理记忆，再维护主体，其余轮次先维护主体，再处理四类记忆。生产 `src` 入口保持 V32，本轮 Golden 使用冻结的 V40 实验。

主体继续为 individual（人、动物）和 organization（组织、团队），保存有来源的名字、别名与描述。联系继续使用无向导航连接。四类记忆为 fact、preference、experience、event。新增来源、记忆及选中的历史关联通过现有六个逻辑集合保存；物理表定义保持原状。

## 顺序与输入输出

1. 当前原文加同会话最近两条消息，进入程序共享召回。
2. 以名字／别名优先、描述其次排列主体候选。路由统计在候选裁剪之前完成，仅当前原文的名称命中参与触发；同一 ID 的多条命中合并，两个不同称呼各命中一个 ID 分别计算。上下文和描述仍提供候选参考。
3. 正常容量为已有 user 加最多五个其它主体。所有同名组候选优先保全；受保护候选超过六席时返回明确预算错误，保留来源与检查点。固定候选之后填充最多八条历史记忆；同名组逐个主体交错获取记忆，记录各主体实际进入输入的历史。
4. 0／1 分支沿用一次主体模型、程序固定身份、一次四类记忆提取。普通记忆继续按来源追加记录。
5. 至少两个 ID 的分支先调用记忆模型，返回 participants、items、reason。participants 包含 ref、当前 mention、可选 target_id 和支持参与角色的 memory_ids；items 包含四类内容、subject_refs、来源及 related_memory_ids。模型选择具体历史记忆及其参与者，同时准备本轮内容；明确新人和证据不足均可先留 target_id=null，供主体阶段判断 create／pending。
6. 程序验证当前提及、候选所有权、历史参与者、来源和引用。选中同名候选需要提供包含该主体的已召回记忆。
7. 第二次模型维护主体，读取当前原文、候选身份依据、记忆阶段选定的历史与准备内容。它保留记忆阶段 ref，维护 create／reuse／pending、别名、描述及主体连接。目标身份冲突或漏掉已有记忆参与者产生字段级错误；依赖未确认主体的记忆进入待定。
8. 程序按已有来源、类型、日期规则编译写入，原子保存主体、记忆、图边、索引与检查点。相关历史通过既有 related 边连接，较早原文及记忆继续保留。

正常两次模型调用。两阶段共享最多一次协议修正，供应商网络重试单列。修正调用中断后按阶段检查点继续，已保存的模型结果直接复用。

## 保留、修改与退出

保留来源、两条上下文、关键词排序、两类主体、四类记忆、字段级校验、共享修正预算、日期解析、幂等和原子提交。修改实验编排，使其按确定性名称路由顺序执行；新增记忆优先的参与者定位协议。原实验主函数中硬编码的单一执行顺序由当前分支编排取代，生产入口及冻结历史实验保持各自用途。

本轮处理记忆的方式继续是追加当前来源的独立陈述。选定历史记忆会保留关联；跨来源覆盖修改、合并删除和完整事件生命周期修订维持现有边界。Search 排序策略保持原样；这次保存的记忆间关联尚未作为新的多跳搜索策略启用。

## 验收标准

- 离线覆盖 0／1／至少两个 ID、别名去重、多个独立名字、上下文／描述、同名候选容量保护。
- 端到端覆盖记忆优先的参与者引用、主体一致性、待定依赖、历史关联、共享修正和中断恢复。
- 用 GPT 对通用同名场景独立重复验证，身份、别名、描述与程序格式分别报告。
- 同一冻结输入跑完整 Golden，统计实际路由覆盖、最终拒绝、主体遗漏、错误复用／创建、记忆待定及检索指标。Golden 未触发的分支明确标为未覆盖。单次 Golden 只支持本轮观测结论。
