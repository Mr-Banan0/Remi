# V23：主体身份的成对 few-shot

## 范围

本轮更新第二次调用的 SUBJECT_EXAMPLES：5 组替换为 10 组输入／输出示例。SUBJECT_PROMPT 正文、提候选 prompt 与示例、普通记忆 prompt 与示例保持一致。身份召回、分类、程序校验、存储和调用预算保持。pipeline 更新为 G11-subject-fewshot-v23，使检查点绑定当前提示内容。

示例使用独立虚构称呼，说明身份判断依据。采用有差异的输入和明确期望输出，参照 [OpenAI Docs 的 few-shot 指南](https://developers.openai.com/api/docs/guides/prompt-engineering#few-shot-learning)。示例只返回生产合同中的 subjects、connections、bindings。

## 模型实际看到的十组示例

| 情况 | 来源要点 | 期望输出 |
| --- | --- | --- |
| 当前用户与动物 | 我是 PERSON_A，也叫 ALIAS_A；我照顾 ANIMAL_B | 用户的三个 ref 合为一个主体，动物另建一个主体 |
| 一个人的两个名字 | 我的同事叫周岚，大家也叫她阿岚 | 周岚／阿岚 refs 一起 create，产生一个 ID |
| 已有人物换职业且有昵称 | 前面说的许澈转做编辑，仍是同一个人，也叫小澈 | 许澈／小澈一起 update 旧 ID，保留新描述词 |
| 同名不同人 | 旧陈露是邻居；今天认识了另一个叫陈露的人 | 即使召回旧陈露，当前 ref 仍 create 新 ID |
| 一只动物的两个名字 | 猫叫松果，也叫果果 | 两个名字一起 create，保留猫描述词 |
| 两只动物同名 | 第一只狗和第二只狗都叫团团，明确是两只狗 | 两个指称分别 create，各自保存团团和狗 |
| 团队改名 | 东港志愿队更名新桥志愿队，仍是同一支队伍 | 两个名称一起 update 旧团队 ID |
| 不同组织简称相同 | 青禾协会与青禾公司是独立机构，都简称青禾 | 两个主体分别 create，各自保留相同简称 |
| 身份内容未变 | 已有用户和组织，当前来源改变志愿联系 | 两个 bindings 复用身份，只更新联系 |
| 同名且身份不明 | 有两个 PERSON_F，当前只说 PERSON_F 发消息 | 留空，当前 ref 保持未解决 |

已用替换后的几组实例展示人物、动物和组织的同一性与差异。用户归属、只读绑定和歧义处理示例继续保留。退出了单独的“动物昵称误提为主体间联系”示例和单独的“同名新组织”示例；新增成对例子覆盖对应身份决策，并减少多种判断混在一个示例中的情况。

## 验证

新增测试把全部 10 组示例送入实际 decode_subjects 和 materialize_subjects，检查 ref 分组、目标 ID、名字与描述词。另有 20 组固定候选场景，使用与示例不同的姓名和来源文字。错误分拆、错误合并、同名误复用的负例测试能够检出语义失败，即使结构校验通过。

真实对照只调用 maintain_subjects。两版使用相同 gpt-4o-mini 配置、相同正文、相同候选和旧主体目录；分别载入旧 5 组或新 10 组示例。期望分组留在本机测试驱动。第一阶段提取与第三阶段普通记忆维护不参与此对照，因此结果仅代表主体维护在给定候选上的表现。没有创建数据库，也没有调用 embedding。

完整离线及真实对照指标见 [主体维护验证](../subject-memory-validation.md)。首阶段误分类／漏候选、同名提及被程序折叠等既有问题继续单独记录。
