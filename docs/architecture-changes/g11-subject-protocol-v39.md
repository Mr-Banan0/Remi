# V39：GPT 主体维护的精简协议与分项诊断

日期：2026-10-23。V39-R2原型完成真实对照，质量门槛未通过；活跃实验已恢复 `G11-subject-prompt-v38-r4`。V39原型保存在冻结目录，生产 `src` 维持 V32，Git 工作区保留未提交状态。

## 目标与现有链路

原文与两条上下文共用关键词召回 → GPT 主体与联系维护 → 程序编译并固定身份 → GPT 提取事实、偏好、经验、事件 → 程序校验及保存。

本次聚焦 GPT-4o-mini 的身份判断、当前提及覆盖和协议填写。单元正常一次主体维护、一次记忆提取；两个阶段共享最多一次协议修正。供应商网络重试单列。主体范围 individual／organization、最多六个主体候选、最多两条辅助上下文及九组英文示例的场景覆盖保持。

## Wire 约定

- create：提供 label={name,kind}，target_id=null。
- reuse：提供已召回 target_id，label=null；程序复制存储主体的名称和类型。
- pending：提供当前原文支持的 label，target_id=null，依赖联系保留未决。
- mention：三种操作均提供当前原文片段；程序检查字面来源，语义身份归属单独审计。
- aliases／descriptions：当前原文中的新增字符串；程序附当前 source_id，保留已存历史值及其来源。
- connections：每项只提供两个 subject_refs，来源由程序附加。

初稿 R1 把操作与 label／target_id 的条件留在 prompt 和程序校验。真实 GPT 回复出现 create 的 label=null、reuse 的 label 非空等违约，R1 全部结果保留。R2 将这些组合写入 items 的 anyOf 操作分支：create／pending 具有非空 label 和空 target；reuse 具有空 label 和候选 target。无候选时仅提供 create／pending 分支。

R1／R2 的普通及修正规则、九组示例和编译函数逐字／AST 核对一致。Schema 是本次 R2 相对 R1 的业务差异；checkpoint 使用独立 pipeline。供应商是否实际执行这些约束，以保存的真实响应及本地校验核实。

## 修正编译的确定性检查

1. 顶层缺失或错误数组在编译后继续保留 contract 问题。
2. 三种操作的当前 mention 都接受来源检查。
3. 固定主体恢复后，错误按主体 ref 重新定位；保护字段的原 wire 错误留在审计。
4. 受保护联系恢复后，错误按端点定位。
5. 缺少 aliases／descriptions 作为新增字段错误，已有有效身份继续保留。
6. 非法 ref 类型保留为明确错误，修正流程继续运行。
7. 模型实际遗漏的字段在下一轮上一 assistant 消息中保持原样。

## 评测与解释

- V38 基线、V39-R1、V39-R2 各使用独立冻结 runtime，GPT 参数保持 temperature=0、max_completion_tokens=6000、timeout=45、每轮 workers=2。
- 每轮保留 46 组既有回归（54 条主体来源）和 12 组补充情境。两批均已阅读，作为当前回归资料；三轮重复用于观察同配置波动。
- 原 passed／checks 保留。新审计分别记录身份操作、当前覆盖、名字／描述、联系、当前提及、机械约束与基础设施异常。
- 描述词条完整性独立于身份匹配。显式期望标注仅存评测侧，冻结后保持哈希不变。
- 原始 GPT wire、编译结果及最终修正结果分别审阅；程序回填字段单列，语义身份准确率留空供人工核对。
- 同名案例无法唯一对齐、元叙述用户指代及其他未裁定语义进入 manual_review。
- 所有真实主体运行使用 MemoryStore；完整离线 SQLite 测试沿用用户此前批准的临时六表。

## 验收边界

先比较错误合并、重复创建、遗漏与错误待定，再查看描述／联系、修正次数、token 与延迟。通过主体门槛后进入完整记忆与检索验证。通用契约问题由程序和 Schema 修复；具体姓名、数据集题目与答案保留在评测侧。

冻结代码、固定输入、每轮原始请求／响应、分项审计与结果位于 `.local-data/subjects-v39-gpt-20261023-v1/`。结果及验收结论见 `docs/subject-v39-gpt-results.md`。
