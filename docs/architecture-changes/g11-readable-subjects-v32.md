# V32：主体阶段的简洁文本输入

## 目标与边界

共用召回 → 主体与关系维护 → 校验并固定身份 → 四类记忆提取 → 程序校验和保存。主体模型读取固定任务说明与按用途分区的文本，返回现有 subjects／connections JSON。正常主体调用一次，Add 总计两次；两个阶段共享一次修正。

## 局部变更

- 新增 `subject_input.py`，将当前原文、补充上下文、主体候选与身份依据、关系有序端点及命题、召回记忆和原文组织为英文文本。每份原文按来源展示一次，身份依据可引用同一原文。原文内的日期与否定等语义完整保留。
- 修改主体固定 prompt 与 12 组独立 few-shot。示例输入与实际输入共用渲染器，示例输出符合当前 source_id 证据合同。已有同名新人示例补充历史上下文。
- 退出主体阶段直接序列化内部 JSON 状态的输入路径。subject provider 正常调用与修正均使用文本；四类记忆提取和 Search 保持各自协议。
- 保持共用召回、原文、别名证据、存储结构、身份／关系校验、输出 JSON Schema、短 ID 映射和调用预算。机器 message_at／observed_at、名称匹配元数据保留在程序状态。pipeline 更新为 `G11-readable-subjects-v32`。

## 验证与完成标准

离线检查文本输入携带来源、身份依据、关系方向、引用范围、修正信息及稳定 ID 还原；执行已有主体与四类记忆回归。真实主体专项复用 V31 的 28 组输入、10 组新增名字样本及 4 组连续维护案例，保持原验收规则，同时单列原规则缺口。真实专项使用 MemoryStore，四类记忆模型调用为 0，物理数据库为 0。冻结代码与输入后执行一次，保留实际 messages 便于核对。结果报告记录语义准确性、程序校验、调用量与耗时；Golden 保持停止。

## 已知解释边界

该实验同时更换固定提示词、输入表达及示例呈现，衡量整体方案。各版本主结果为单次观测，效果归因及同一输入的失败概率需要独立实验。主体语义准确性由真实模型验收评估，结构校验结果单独记录。
