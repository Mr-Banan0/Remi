# V21：先确认身份，再输出主体与关系增量

本轮重写主体维护 prompt 与示例，明确身份判定、主体分组、身份绑定、主体增量及关系增量的处理顺序。生产输出合同、校验器、召回、存储和调用预算沿用 V19。第一次调用与第三次调用的 prompt／示例内容均与 V19 一致；各阶段的附加引用协议分别描述自己的字段。

| 部分 | 处理 |
| --- | --- |
| 保留 | V19 提候选及记忆维护提示、三阶段、gpt-4o-mini、六表、来源、身份召回、增量合同、程序校验、检查点和一次共享修正 |
| 修改 | 主体 prompt 改为按顺序确认身份、选择主体处理、检查关系、校验整体输出；补齐同名、待定和关系更新示例 |
| 新增 | 分阶段引用协议；对示例进行字段、来源、身份目标、参与者及关系端点一致性检查 |

## 主体 prompt 中文说明

围绕提供的候选确认身份，再返回 subjects、connections、bindings。原文属于带有说话人和来源归属的证据数据。候选及召回命中属于待判断的提议。处理范围使用提供的主体 ref 和联系候选 ID。

### 1. 确认身份

先判断候选在当前来源语境中指向谁，再比较已有名字或标签。

将同一个主体的提及分为一组。明确命名、明确回指和连续语境可支持同一身份。名称相同、描述相同、lookup_names 相同、召回仅有一个命中，都只提供身份候选；复用需要语境中的身份依据。

原文明确区分的主体各自分组；同一人的属性变化也可以属于同一个人的历史。身份含糊或提及无依据时，该 ref 保持未确认。

@user 按来源归属表示真实对话发言者。具名引文／文档说话人保留自己的身份。主人及其公司、动物分别维护。

### 2. 为已确认的身份组选择处理

- 明确的新主体：subjects 中使用 create，target_id 为 null，ID 由程序分配。
- 确认是旧主体，新增有依据的名字／标签：subjects 中使用 update，选择目录内的旧 ID。
- 确认是旧主体，名字／标签保持原状：bindings 中选择旧 ID，供后续记忆与关系绑定。

每个 ref 在 subjects 和 bindings 中合计出现最多一次。已确认的参与主体保留处理结果。主体补丁接受所选 ref 自带的候选名字及描述词，程序保存这些内容和证据；共享描述词可以用于多个主体。身份维护在选择补丁时确认这些候选内容属于该身份。

### 3. 根据确认后的身份处理关系

联系候选需要表达两个不同、已确认主体之间可持续维护的关系。身份等同通过主体分组表达，类型／角色通过候选描述词表达，具体发生的事件进入独立记忆阶段。同一主体的两个称呼合并后，二者之间没有独立主体关系可创建。

connections 仅选择输入中的 candidate_id。新关系使用 create、target_id=null。更新同一对主体、同一表达模式、同一关系方面的状态时，使用 update 并选择 relation_catalog 中的关系 ID。其他关系方面单独创建；已存在且没有变化的关系省略修改。程序复制候选端点、原文、来源和模式。

每个被选择的关系端点，都由主体补丁、只读绑定或已经固定的 accepted_subjects 提供身份。

### 4. 核对整体输出

subjects=[] 只表示没有主体修改；connections=[] 只表示没有关系修改。bindings 继续记录本轮已确认、无需修改的旧主体。省略表示身份未确认。

依次核对身份组、端点身份、关系目标和操作。修正时接受项保持固定，程序沿用已接受结果，模型处理失败或未确认的工作。输出保持既有字段，程序负责 ID、校验与持久化。

## 示例覆盖

示例分别覆盖：新主体与别名归组；有明确回指时补充旧主体别名，并舍弃称呼间的错误联系候选；明确另一个同名主体时新建；主体不变而关系改变时提供 bindings；同名旧主体缺乏区分依据时保持未确认。示例使用占位符，生产代码不包含评测人物、题目、答案或针对测试集的分支。

## 运行版本与范围

当前 pipeline 为 G11-subject-prompt-v21，JSON schema_version=12。旧版本未完成请求按既有来源重放规则处理。

本轮先测试了同时改动三阶段的 V20，真实回归出现新增漏提。V21 恢复 V19 的提取／记忆提示，仅保留主体 prompt 与引用协议修改，作为范围更小的对照。V20 和 V21 各自冻结代码并独立保存结果，测试输入与判分保持一致。

候选按名称整理、上下文同名证据重挂、精确别名召回和附带标签整体接受等现有程序行为保持原状。它们仍可能限制模型判断；测试中观察到的错误按实际阶段记录。

提示词组织参考 OpenAI Docs 的[官方提示词指南](https://developers.openai.com/api/docs/guides/prompt-engineering)：用清晰边界组织规则，并使示例覆盖不同输入与期望输出。当前模型及网关配置沿用用户已有配置。
