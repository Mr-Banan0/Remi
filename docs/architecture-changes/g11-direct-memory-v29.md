# G11 V29：主体维护后直接提取并保存四类记忆

日期：2026-10-22。用户明确提出暂时移除记忆维护模型。本轮范围为生产链路、提示及 Schema、离线回归和当前说明；历史 Golden 结果保留原归属。

## 链路与调用预算

原链路：共用召回 → 主体及关系模型 → 固定身份 → 四类候选提取模型 → 四类记忆维护模型 → 校验提交。

当前链路：共用召回 → 主体及关系模型 → 固定身份 → 四类记忆提取模型 → 程序校验并追加保存。

每个用户文本单元正常两次模型调用，两个阶段共享一次协议修正。网络重试和并发重算单列。提取项目直接带 record_type、content、subject_refs、mode、context、status、time_expression、evidence。程序复制来源证据并分配 ID。

旧路径退出是为了落实当前直接提取保存的单链路，来源与程序一致性校验继续生效。原有独立事件修订断言更新为追加保存与历史不变断言；通用时间、身份、来源、并发、持久化、HTTP 恢复测试继续保留。实际历史实验及其冻结运行时保持原样。

## 校验与保存

1. 提取字段遵循四类型合同，主体 ref 选择本轮固定视图，来源 ID 选择已提供的原文。
2. 每项引用当前来源；纯上下文项目记录 context_only 并跳过本次写入。
3. 未确认主体依赖保留 pending；独立有效项目继续保存。
4. 事实、偏好、经验使用内容表达时间范围；事件提供状态，日期表达由原文与消息时钟验证，未知时间使用 null。
5. 程序生成新增记录、修订、来源边与主体参与边。主体关系操作来自主体阶段并继续校验端点、方向、模式及旧命题锚点。
6. 记录、图、检索索引与应用检查点一起原子提交。向量故障复用已完成输出，主体／关系并发变化触发快照重新计算。

四类记忆暂按来源追加。改期和完成也形成新事件陈述，旧记录保持原样。不同来源的重复内容可以同时存在；同一请求重试保持幂等。主体语义错误及模型提取准确性继续独立衡量。
