# Remi G08：候选、联合维护与版本图

实现状态由 verification.md 与具体实验报告记录。G08 使用单条 Add 生产链路，Jev 用于 Search 证据重排。存储沿用已批准六表，记录字段通过 JSON 扩展。

## 写入流程

1. 程序保存完整 Source、角色、消息时间、请求指纹及阶段检查点。每条用户消息形成处理单元，长原文按连续窗口覆盖。
2. GPT propose 提出带引文、实体提及与可重叠标签的候选。原文提供断言，上下文解释指代和明确确认。
3. 程序按名称及有来源的别名获取候选实体，在主体范围内混合召回，并用小额度跨实体与原文检索补入口。每候选最多 8 条旧记忆，合并最多 24 条；召回覆盖全部记忆标签。当前版本使用有界排序，边际收益广度搜索另行讨论。
4. GPT maintain 联合选择实体身份、记忆目标、操作与连续性，输出最终内容、证据、时间、角色、实体断言及跨记忆联系。每个候选对应明确编辑或舍弃理由。维护目标以开放关系的主体与规范谓词校验：独立关系另建，唯一匹配的既有关系可复用；目标调整写入检查点。关系对象或否定状态改变时形成替代修订。不同日期的新完成事件保留独立发生身份，明确纠错可修订原事件。维护输出使用 write＋target_id 表达写入：空目标新建、已有目标更新；程序据此生成最终操作。断言端点缺少显式角色时，程序从断言结构补齐参与角色。
5. 程序校验来源片段、所有权、端点、目标及时间。一次计划中的对象、记忆修订、边、检索文档和应用检查点一起提交。外部调用在事务外完成。
6. Add 成功返回时，对应图与索引已可读。供应商或输出故障保留 pending 检查点并返回可重试状态。已完成阶段在相同请求重试时复用。

普通有效单元两次 GPT；空候选一次 GPT。两阶段共享最多一次输出修正；传输暂态重试受请求剩余预算约束。embedding 以候选召回及索引批量执行。Add 180 秒、Search 45 秒为默认合作式预算，超长请求通过检查点继续。

## 图与身份

Source 保存证据；GraphObject 保存实体身份及有来源、带观察时间的别名；Memory 保存稳定记忆身份和 revisions；Revision 保存标签、内容、证据、时间、状态、实体角色、实体断言与跨记忆联系。

关系投影由程序从 Revision 生成：

- involves：Memory 到实体，label 表示参与角色。
- assertion：实体到实体，label 保留开放关系描述。
- related：Memory 到 Memory，label 描述有依据的联系。
- supported_by：Revision 到 Source。
- revises：新 Revision 到旧 Revision。

每条边记录支持它的 revision_id、memory_id 和来源。跨记忆联系同时绑定目标修订，后续目标更新保留原联系的历史含义。当前关系由问题时间可见的记忆版本决定。当前对象集合由可见修订的角色导出；历史角色随旧版本保留。

新状态 replace 明确开始新有效阶段；confirm/supplement 保留既有区间并按证据补充。视图根据后来的替代关系计算旧状态结束边界，已保存的历史证据保持不变。计划、愿望、已发生、取消、撤回分别保留。

## 检索

保留原文及记忆 BM25＋向量检索、一次 GPT 决策、最多两步补搜与 Jev 重排。图读取使用当时可见的角色、实体断言和跨记忆联系，最多 graph_limit 条。self 的广泛成员关系提供身份组织信息，具体实体和显式关系提供有界扩展。

持续背景按 temporal_scope、状态、有效区间与来源时钟决定。短期状态描述报告日期；未知结束时间记录 unknown。完整历史继续参与冷检索。返回证据保留角色、时间、状态和原文引用。

## 变更与数据边界

保留 HTTP Add/Search 合同、六表 SQL 结构、日期解析、混合检索和证据重排。旧 Add route/classify/select 以及固定目标后的 materialize 路径退出；propose/maintain 接管这些职责。Jev Choices 模块及专用验证脚本随旧 Add 合同移除。

G07 冻结代码、实验库及结果继续独立保存。G08 从原文按时间重放到独立实验库。请求检查点绑定 pipeline 版本，版本冲突返回明确错误。生产代码使用一套当前记录模型。历史报告分析工具保留读取既有外部实验报告格式的能力，用于对照审计。

证据输出使用来源 ID；程序从本次可见原文窗口复制证据，模型专注于候选及维护判断。来源所有权继续校验。缺少可解析端点或原文值支持的可选断言保留审计处置，已校验的记忆内容和参与关系继续提交。语义支持仍通过真实模型实验单独验收。

图元数据是经校验的记忆附加投影。未声明主体、未使用实体、缺少来源名称支持或未知可选联系会被排除并写入 graph_dispositions；来源 ID、所有权、维护目标和候选覆盖校验继续决定计划能否提交。实际图完整度单独统计，关系处置与语义 bad case 保持可见。

维护编辑通过 candidate_ids 自动继承候选的原文证据。模型在 evidence 中选择额外历史来源，用于保留旧细节；本次输入的来源连续性由程序建立，减少第二阶段重复引用造成的遗漏。

同一计划中，同一维护目标、相同时间／状态／作用域的多项 write 由程序合成一个最终修订，逐段保留内容并去重来源、角色与关系，记录 write_compositions。时间或状态冲突继续要求模型联合解决；每个目标在一次提交中形成一项最终写入。

Add 模型边界使用短引用目录：S 表示来源，M 表示旧记忆，E 表示既有实体。用户范围和修订 ID 由程序持有。程序在请求前映射，在输出后还原真实 ID；原文与记忆正文保持原词。目标所有权和召回范围校验继续使用真实 ID。Search 沿用既有引用协议。

输出故障后的相同请求重发，将上一轮失败及具体校验信息传给尚未验证的阶段。已验证阶段继续复用；重发阶段单独记为 resume 调用，普通流程与共享一次输出修正预算保持一致。
