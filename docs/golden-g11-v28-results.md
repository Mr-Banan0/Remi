## 写入失败定位

| 待定产生环节 | 数量 | 解释 |
| --- | ---: | --- |
| 普通记忆模型主动 pending | 162 | 最终维护模型直接选择待定 |
| 身份依赖校验 pending | 83 | 候选引用了仍未固定的主体，程序保留待定 |
| 关系处置 pending | 7 | 主体／关系阶段未形成有效关系操作 |
| 其他程序校验 pending | 7 | 包括普通 keep 指向关系等权限／类型问题 |
| 合计 | 259 | 占 266 个候选处置的 97.37% |

1. **主体边界在主体维护阶段失效。** 实际保存 bean trellis、spiced pickles 为 organization，西瓜为 animal，上海为 organization。原文分别描述菜架、食物和居住地点。模型把范围外名词塞进合法枚举，程序的类型枚举与字面来源检查仍然通过；这些检查能证明引用有来源，对名称是否属于该类型的语义覆盖有限。
2. **跨轮身份复用不稳定。** 主集 Jasper 有 3 个主体 ID，Mrs. Patel 有 2 个。Mrs. Patel 的两次建立即出现在同一天连续的帮忙搭菜架、随后喝茶收泡菜的邻居场景。姓名相同本身不足以合并，此处同时存在连续原文语境。逐个主体、来源和 ID 已写入 analysis.json，进一步归因需要对照该轮召回目录与模型选择。
3. **普通维护对可记录内容过度待定。** 首轮 Nashville 早上 6:30 起床的经历已进入候选，主体已确认，维护模型仍以经历需要更多语境为由 pending。候选把起床、疲惫与打算等内容合在一段，粒度问题作为观察保留；直接拒绝发生在最终普通维护阶段。
4. **偏好被错误要求关联事件。** 生命周期第一轮“李明计划在2026年9月22日从北京搬到上海。李明喜欢西瓜。”的主体验证通过。维护模型对搬家称上下文不够明确，对喜欢西瓜称缺少特定事件关联，两项均 pending。偏好本应可以独立保存，trace 已证明该处失败发生在普通维护模型。
5. **主体合同错误额外触发修正与依赖待定。** 诊断记录包含重复选择同一 ref 45 次、证据未匹配提供原文 41 次等问题。一次诊断可包含多个错误，计数用于定位，按独立失败请求统计需要另行去重。

上述观察分别来自主体决策、程序依赖验证与普通维护输出，完整输入输出保存在 result.json 的 derivation，代表性普通待定样本保存在 write-examples.json。
