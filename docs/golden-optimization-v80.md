# V80 / remi-0.2.14：分别查询可独立核验的前提

针对“在某天发生某活动，并询问后续细节”的问题，Planner 分别查询那天的实际活动，以及该活动在历史中的实际发生、日期和结果。第一路保留日期，第二路开放日期范围；单一前提继续允许一路搜索。两路均使用现有 premise_check，JSON schema、补搜上限和默认模型调用次数保持一致。新的野餐示例替换旧的单路示例。

独立真实模型测试包括相机维修、驾驶考试、剧场演出、水族馆参观、已确认订房、延期航海课程。旧版的五项前提问题均只返回一路，新版五项均返回两路，第二路日期开放。普通订房问题仍分类为 direct。部分第一路仍带入了假定活动，所以不能将协议正确等同于完整的语义解耦。

另设保留集：中文搬家、英文资助申请、普通事实、时间先后、当前状态、行动建议。实际生产补丁复测六项模式均符合预期；两个前提问题日期／活动范围拆分通过。行动建议仍可能跑偏或把行动日期用于历史检索，本版未声称解决该问题。记录位于 `/private/tmp/remi-premise-split.json`、`/private/tmp/remi-premise-holdout.json`、`/private/tmp/remi-v80-premise-holdout.json`。可复现脚本为 `scripts/validate_premise_planning.py`，结构统计与人工语义检查分别报告。

全套离线回归 510 项通过。后续验证采用同一 V76 查询边界数据库，分别调用旧版与新版真实 Planner，其他 Search 设置保持一致。该实验先比较候选覆盖、排序与耗时，再决定是否进入完整顺序 Golden，避免把写入波动混入前提规划的比较。
