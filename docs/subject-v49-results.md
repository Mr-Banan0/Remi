### 程序兜底与验收边界

名字或别名命中多个同类型 ID 时，程序只接受具有唯一身份依据的 reuse；缺少唯一区分证据时进入 pending。create 与已召回的别名重合，或在新增别名时与已有本名重合，会进入一次共享修正。修正可以复用旧 ID、保留 pending，或再次 create 以确认原文明确表达的新主体。模型选择 reuse 且当前名字唯一命中时，程序从该名字对应的身份依据补全 basis。

验收器直接检查本轮绑定结果：Ray 必须复用 Rhea；Selene 更新只绑定 Selene；两个 Esra 缺少区分信息时不绑定任一旧 ID；动物 Vale 的当前指代不绑定人物 Vale。历史主体库中保留正确对象无法再掩盖本轮错误决策。

当前结论：这组三类主体测试中，明确同名新人、同名歧义、唯一别名复用和上下文候选过滤均已闭环。本轮验证范围是主体专项，没有运行完整 Golden。
