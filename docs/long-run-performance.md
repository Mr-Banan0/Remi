## 已实现

- Search 的 mentions 查询按种子起点、主体终点访问；related 双向读取种子邻接边，复用本轮可见版本映射。
- SQLite 端点查询明确使用 edge_origin / edge_target。实测 ORDER BY id 曾使优化器选择仅按 owner 的主键索引，显式访问路径消除了这一扫描。结果仍按边 ID 排序。
- Add 提交时按被维护记忆及其修订 ID 清理旧结构边，保留版本绑定的 related 历史边。
- get_many 分批读取缺失记录，保持输入去重顺序、用户边界及原有缓存失效规则。
- 来源可见性和邻近消息定位读取 source_headers，只向 Python 返回时间、会话、角色等必要字段。SQLite 仍需读取记录 JSON；此项减少结果传输和 Python 正文实例化，未改变物理存储布局。
- Add 在选定维护候选后加载原文、排序证据并计算维护指纹。候选召回与维护选择规则保持一致。
- 版本链输出使用文档 ID 映射，避免对每个输出节点重新扫描文档列表。
- engine.last_performance 提供请求级阶段耗时、返回记录数、向量候选数、用户锁等待和持有时间。ContextVar 隔离并发请求，异常退出也释放上下文。诊断保留数值和阶段名。

计时是包含子阶段的墙钟时间，嵌套耗时分别观察；返回记录数表示读取结果数量。物理扫描量、CPU 时间、外部纯网络耗时与模型输入 token 仍需结合查询计划、profiler 和已有 provider calls 记录判断。last_performance 是最近完成请求的本地诊断，持续服务现已通过鉴权 /metrics 提供累计工作量与最近 1,024 次请求分位数，并支持无内容请求日志。

## 派生视图与统计复用

同一次 Search 的可见记忆投影在元数据筛选、版本链、图导航和热状态选择之间复用。缓存键包含存储实例、owner、查询时间和变更令牌。词长统计读取一次，各查询候选子集继续独立计算 BM25 的平均长度和文档频率。

缓存按估算 Python 对象大小限制为 32 MiB、最多 32 项，请求退出或异常后释放。本连接写入、回滚和其他连接提交使令牌变化。SQLite 只读快照内的数据保持一致，缓存也对应相同快照。容量不足时完成正常计算并返回结果。这里完成了请求内重复工作消除。后续增量投影已将轻量历史元数据持久化，并按单条记忆写入更新；查询时间下的版本筛选仍在 Search 执行，完整正文按命中加载，见当前进度。

## 快照并发与迁移

新建数据库使用 WAL。Search 使用独立只读事务，读取同一个已提交快照，正常链路模型调用数量保持原样。每个 SQLiteStore 默认最多同时开放 4 个读快照，部署服务器配置为 1 个，容量等待遵守请求 deadline；异常时释放连接和额度。快照结束后用短事务重新读取最新记忆，仅合并访问时间。

记忆维护的冲突指纹覆盖语义状态，访问热度单独合并。Search 写回热度能够与正在运行的 Add 共存，真实修订变化继续触发冲突校验。已有测试验证慢 Add 期间 Search 完成、Search 期间 Add 提交后返回旧快照、最终热度写回保留新修订。

现有 rollback-journal 数据库继续使用原串行读取路径，这是已有部署迁移窗口的兼容路径。所有部署完成 WAL 迁移并通过回归后可以删除。显式迁移命令：

```sh
remi enable-wal --path /path/to/memory.sqlite3
```

投影阶段先验证测试副本，2026-11-05 已在备份及恢复演练后迁移广州部署库。WAL 快照会在读事务存续期间保留所需 WAL 页面；请求超时、4 个并发快照限制和数据库/WAL 容量监测共同约束资源。读连接缓存随请求关闭释放，此阶段优先保证快照一致性。

## 运维基础

显式运维命令：

```sh
remi inspect-db --path /path/to/memory.sqlite3
remi backup-db --source /path/to/memory.sqlite3 --destination /backups/new-snapshot.sqlite3
remi restore-db --source /backups/new-snapshot.sqlite3 --destination /recovery/new-memory.sqlite3
```

检查输出完整性、六表记录数、数据库与 WAL 大小。备份使用 SQLite backup API 捕获已提交 WAL 内容，验证后原子发布到新文件，文件权限为私有。恢复使用相同复制与验证过程，目标路径须为新路径。超时清理临时副本，保留原库和已有目标文件。备份产物使用独立单文件格式，恢复后显式启用 WAL。

owner 锁登记按使用者计数，等待者和递归调用使用同一把锁，最后一个使用者退出后回收；避免长期服务因历史用户增多而持续累积空闲锁。
