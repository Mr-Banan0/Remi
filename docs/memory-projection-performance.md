# 长期检索：增量轻量投影验收

## 实现范围

基于 6a5eb92 的工作区改动；未提交、未运行在线 Golden、未迁移业务库。六张业务表和现有 FTS 表保持原有集合，memories 增加 search_projection 列及更新失效触发器。业务 record_json 和原始修订保持完整。

Add 或访问热度写回某条记忆时，在同一事务内更新其轻量投影。投影包含记忆类型、置顶/影响/访问属性以及各修订的 ID、来源、观察时间、创建时间、表达方式和状态。读取按查询时间筛选修订，仍使用 observed_at、created_at、id 的原有当前版本规则。

Search 首次读取轻量投影，图导航和热状态选择使用同一份元数据；版本路径和热状态入选后再按 ID 加载完整记忆。它替代了全量 Memory/Revision 模型校验、正文深拷贝以及超过缓存预算后的重复构造。请求主流程显式传递同一视图，即使派生缓存容量不足也保持一次构造。

## 规模对照

同一旧版生成的数据库先复制为两个独立且 SHA256 一致的副本，再分别运行冻结基线和当前代码。10% 记忆含三个修订，包含后补录的历史状态；约 10% 记忆具有版本绑定 related 边。数据跨约四年，向量 1024 维。当前时点及历史时点各重复三次，无外部模型。每个规模六次响应哈希全部一致。

| 记忆数 | 当前查询中位数：前 → 后 | 历史查询中位数：前 → 后 | 峰值 RSS：前 → 后 | 数据库体积变化 |
|---|---|---|---|---|
| 10,000 | 3.280 → 0.623 秒 | 0.730 → 0.442 秒 | 243.8 → 131.1 MiB | +12.8% |
| 50,000 | 19.068 → 3.929 秒 | 14.308 → 2.531 秒 | 975.6 → 346.8 MiB | +12.8% |
| 100,000 | 38.375 → 7.700 秒 | 28.299 → 5.476 秒 | 1877.2 → 611.9 MiB | +12.7% |

峰值 RSS 为独立进程全生命周期上界，修改后包含迁移过程；查询中位数为三次本地运行，属于偏暖态实验，未测生产 P95、并发吞吐或冷盘性能。

| 规模 | 单条记忆持久化中位数：前 → 后 | 一次迁移耗时 |
|---|---|---|
| 10,000 | 0.068 → 0.087 毫秒 | 0.321 秒 |
| 50,000 | 0.096 → 0.098 毫秒 | 1.423 秒 |
| 100,000 | 0.095 → 0.090 毫秒 | 2.754 秒 |

十万条当前查询：旧版累计构造 500000 条完整记忆、600000 条完整修订（含重复构造）；新版读取 100000 条轻量记忆头、120000 条轻量修订头，完整记忆读取 76 次。计数表示应用层工作量及返回记录，不等同 SQLite 物理页扫描。

## 迁移与失效

```sh
remi project-memories --path /path/to/test-copy.sqlite3
```

先在副本验证与备份，再在维护窗口更新所有写入进程并迁移业务库。旧版二进制的按列数 INSERT 与新增列不兼容，回退旧二进制应使用迁移前备份。新版本读旧库时从原始记录构造相同轻量投影，启动和查询均不自动修改 schema；该分支服务实际部署迁移窗口，全部库迁移并验收后可删除。

对 record_json 的 SQL UPDATE 会把投影置空，查询从原记录构造正确元数据；显式 project-memories 可重新补齐。正常应用写入在同一事务内完成记录和投影写入。插入后未提供投影的记录同样走原记录构造。访问热度、删除及事务回滚使用原存储一致性机制。

## 性能边界与复现

本阶段减少正文解码、Pydantic 构造和重复视图计算。Search 仍读取全量轻量记忆/修订头、文档元数据和来源头，执行精确向量比较；成本仍随总量增长。当前视图在查询时间上选择，存储的投影覆盖历史修订，适用于历史问法与补录。没有引入 ANN、Redis、自动淘汰或新的模型调用。
