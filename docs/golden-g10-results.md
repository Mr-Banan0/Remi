124 个候选有身份对齐问题。身份审计中 `user` 出现 119 次、`the user` 出现 1 次；其余包括名称缺少所引来源支持的情况。提示已要求第一人称使用 `self`，实际提候选仍频繁输出 `user`。程序只将 `self` 绑定到 API 用户，其他名称要求原文支持，因此产生 identity issue；维护阶段也没有改写候选身份的权限。这是提候选与程序对齐之间的协议缺口。待定提示和原文继续参与检索，正式图和背景视图中缺少这些卡片。

物理调用：propose 163、maintain 163、maintain_repair 11、embedding 367、search_decision 16、rerank 58。propose／maintain 单次均值为 3.40／3.18 秒，G08 为 5.32／8.99 秒，G09 为 7.61／12.49 秒。调用合同更小、维护输出更短，同时较多候选转入待定，提速伴随写入内容和结构变化。当前结果支持“这版运行更快”，召回和语义维护质量继续按各自结果验收。
