## 内容准备与分类

RHELM 初始生成 434 个断言，276 个把本条用户来源 ID 再填进 context_source_ids。程序将其视作未知上下文，触发修正；大量修正仍保留错误。另有改写、跨回合引用造成的引文校验失败。

最终只有 53 个断言通过准备，进入 Jev；36 个接受操作，来自 24 个回合。159 个回合中 135 个最终没有结构化操作。完整原文都已保存并索引。最终处置记录有 224 条 context_source_unknown、157 条 new_user_source_quote_required、5 条 prepare_repair_position_invalid；这些是逐断言错误记录，不能与失败回合数等同。

53 个断言的 Jev 分类：Event 23、Fact 3、Preference 8、Experience 2、raw_only 14、uncertain 1、连接失败缺少判断 2。类别数量反映实际选择，RHELM 没有内部类型标准标签，本轮没有计算全局分类准确率。

人工核对确认仍有边界问题：

- “对采访文案感到有精神”“感谢学校团队支持”被写成开放有效期 Fact，来源主要表达当时的反应。
- “愿意分享这次故事”被写成持续 Preference；“很高兴 Alicia 承担场地安排”被写成 Preference，实用内容是项目责任与背景。
- “修好音频感觉小胜利”被写成 Experience，内容缺少可复用经验结论。
- 第三条 Fact 提供“难以坚持卧床”的真实线索，但弱化了遵守卧床要求的具体限制。CrossFit 决策已经看见并选中它，补搜仍转向训练设备和上次训练时间，卧床与拐杖的标注原文没有补齐。

对象提取也回退：G02 测试库有 36 个对象；G05 RHELM 只生成 self，生命周期只生成李明，合计 2 个对象。当前关系读取排除宽泛 self 邻域，所以人物／项目关联扩展在这轮 RHELM 中没有发挥作用。内容准备和对象抽取的质量需要与 Choice 操作选择分别诊断。

未知时间 Event 从 60/102 变为 19/22。多数有效准备仍使用未知时间，这会限制基于事件时钟的工具。

## 全部 update 审计

RHELM 两版均只有 1 条接受 update，retract 均为 0。新版本是 4 月 19 日给学校团队发感谢邮件的后续补充；新原文明确说 those emails，目标是同一天邮件事件，身份匹配成立。旧版是 Asheville 打包事项的再次确认，身份也成立。

逐条核对错目标数量均为 0/1；这个样本量无法证明改进。新更新正文重复了旧来源段落，混用 User 与第一人称，保留了相对时间，遗漏照片尤其包含 Jasper 画作的细节。正确目标选择与正文质量是不同指标。

生命周期本轮没有 update。首条计划和偏好在 Jev 分类连接失败时退回原文；改期与完成消息因上下文来源绑定失败被处置。最后一条独立杭州搬家才创建 Event 与住所 Fact。2/3 原文查询命中不能代表完整结构化生命周期已经建立。

准备与修正共 38 分钟，约占 Add 累计调用时间的 90%。155/159 个 RHELM 回合用掉修正额度。Jev Add 两轮总耗时约 2.13 分钟；本轮最明确的 Add 瓶颈在它之前。

G02 记录到 109 次修正，因历史统计缺口为下界；G05 157 次。历史 report 与 journal 覆盖不一致，对照使用记录更多的 report；新 journal 与最终 report 请求计数一致。G05 程序因续跑仍将完整统计标志保守设为 false，实际诊断按完整持久日志核对。

本轮物理供应商连接错误 16 次：GPT 准备 2、Search 决策 2、向量 7、Jev 分类 2、Jev 重排 3；没有观察到 HTTP 400/402/429。6 次 Add 503 均来自向量连接失败。重排部分连接失败使人员参与题退回基础顺序，产生一项明确可用性干扰。恢复始终使用同一冻结代码及原检查点。

## 验证与结论

真实 Choice 冒烟使用独立合成文本：两次 HTTP 200、14 项判断均符合预期，选项顺序反转后选择一致；耗时 2.34／1.52 秒。这个验证证明接口合同可用，不能代表实际记忆质量。离线回归 171/171，通过来源范围、固定目标、内容写入权限、部分失败、同目标多项更新、共享修正和断点复用等检查。

报告发布时补齐分阶段结果分析及 David 的 Jev 调用日志适配，最终离线回归 172/172、9.45 秒。补充仅涉及诊断脚本、测试与说明；核心 Add/Search 代码和冻结 Golden 结果保持原样，没有额外付费运行。

当前分阶段执行合同已落地；常规成绩、分类内容与耗时都没有达到替代旧版的验收要求。首要问题是我在内容准备阶段保留了过多需要模型填对的机械字段，特别是上下文 ID 和逐字引文，导致多数断言在进入 Jev 前被丢弃。Jev 分类仍有具体错误，真实 update 样本仍很少。此次实验支持继续区分准备、分类、目标选择和正文生成的责任，也明确表明目前实现尚未带来整体收益。
