# User 身份修复与验证

2026-10-20。改动前工作区按用户指令提交为 `e6ba7ae`（`feat: simplify memory maintenance and record G10 Golden`）。本轮改动保留在该提交之后的工作区。

## 当前结构与局部变化

| 步骤 | 当前处理 |
| --- | --- |
| 提出候选 | 必填 `user_involvement=involved/not_involved/uncertain`，描述当前用户是否参与这条具体命题。其他主体名称按原文复制，程序根据参与标志生成唯一 `user` 引用。至多 12 个原文名称加 1 个程序用户引用。 |
| 来源名称检查 | 校验名称是否出现在所引原文中。生成名称或翻译名称造成的确定性缺口使用现有共享修正额度；仍有问题时，受影响候选按身份待定处理。 |
| 身份与召回 | 当前用户使用 `stable_id('obj_', owner, 'user')`，节点为 `name=user/is_user=true/kind=person`。每个用户分区保持一个稳定 ID。其余主体沿用原有来源名称、别名与知识时间规则。程序将已解析主体交给维护阶段复核。 |
| 维护定稿 | 新卡片必填确认后的参与情况。两阶段明确判断一致后创建；相反判断触发有界复核，仍有冲突时保存为待定。候选原先为 uncertain 时可结合原文解析。keep 核对目标卡的参与情况；事件补丁继承原主体与参与标志。 |
| 物化与检测 | 修订保存参与情况。模型声明、当前用户 ID、主体节点、mentions 边、卡片归属和边起点保持一致。漏边、漏节点、错误所有权或修订字段缺口阻止提交，原文与阶段检查点保留。 |
| 提交与恢复 | 主体、记忆、图边、索引和应用检查点继续原子提交。向量阶段失败后复用候选与维护结果；同用户串行、幂等和历史版本冲突保护持续生效。 |

来源作者、命题参与者和引语说话者各自保留归属。模型先识别命题中的行动者、体验者、状态／偏好持有者和关系端点，再判断当前用户是否在其中。他人的偏好、文档中的叙述者、虚构人物和通用角色按各自身份表达。

普通单元仍为两次 GPT，空候选一次；两阶段共享最多一次输出修正。局部召回继续排除通用 user 枢纽扩展，维持已有全局补召回和图读取预算。事件分类、关系维护权限、Search/Jev 和日期解析沿用 G10。

`requests.units` 中保存三组诊断：

- `user_reference_checks`：程序构造或移除 user 引用的依据。
- `proposal_name_checks`：按阶段记录原文名称缺口，修正后仍有问题的项可追溯。
- `user_involvement_reviews`、`user_binding_checks`：两阶段判断及最终操作、修订与图边检查结果。

JSON 记录版本更新为 `schema_version=11`，检查点为 `G10-user-identity-v8`。物理数据库继续使用既有六张表。本轮删除旧 `self/is_self` 生产路径，使模型协议、节点 ID 和程序判断收敛到同一名称。HTTP 请求结构保持原样；旧实验通过各自冻结代码读取，从原文重放生成新版本记录。
